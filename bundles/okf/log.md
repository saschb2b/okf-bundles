# Change log

## 2026-08-05

* **Creation**: Built the `okf` bundle: OKF explained as a conformant OKF bundle. An `overview.md` entry point plus six domains and a references folder.
  * `context/` (4): the context window, context assembly, the knowledge gap, scattered knowledge.
  * `approaches/` (8): prompt stuffing, fine-tuning, retrieval, the four retrieval failure modes, tools and MCP, briefing files, format versus protocol, OKF versus retrieval.
  * `spec/` (13): bundle, concept document, concept ID, core frontmatter, body conventions, extensions, cross-linking, index file, log file, conformance, versioning, design principles, non-goals.
  * `trust/` (8): why trust became a field, sources, generated and verified, trust tiers, the actor convention, lifecycle, attested computation, verification versus attestation.
  * `practice/` (9): authoring, consuming, progressive disclosure, validation, graph hygiene, migration from v0.1, distribution, external references, the adoption path.
  * `ecosystem/` (6): knowledge-catalog, the sample bundles, the okf skill, OKF Studio, okf-bundles, llms.txt and sitemap.xml with ODSF.
  * `references/` (2): the v0.2 specification with a section-to-concept map, and Google's announcement post.
* **Update**: Removed `references/okf-talk.md` and every citation of it. A conference deck is a temporary artifact, so it should not be load-bearing provenance for a bundle other people will read. The claims it carried were either replaced with a verifiable published source (each URL fetched and checked before citing) or left as unsourced analysis. The bundle is now 51 concepts.
  * Added: Lewis et al., *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks* (NeurIPS 2020) to the retrieval and fine-tuning concepts; Liu et al., *Lost in the Middle* (2023) to the context and retrieval-failure concepts, with a new section on position inside the window; `agents.md` to the briefing-files concept; the MCP and `llms.txt` specs to the neighbouring-layer concepts.
  * Corrected: `approaches/briefing-files.md` claimed briefing files are "completely bespoke per team". `AGENTS.md` is in fact an open convention under the Linux Foundation's Agentic AI Foundation with 60,000+ projects using it. The concept now makes the sharper and accurate claim, that the convention standardizes the file's location and not its content.
* **Update**: Filled five gaps in `approaches/`, which previously covered only the five moves from the talk's framing and left out the categories people actually raise as objections. Now 56 concepts.
  * `skills-and-procedures.md`. Agent Skills as the closest neighbour: a folder of markdown with a `SKILL.md`, loaded by three-stage progressive disclosure, which is the same mechanism as `index.md` applied to procedure. Draws the how-to-do versus what-is-true line, and is honest that the formats overlap because skills also carry domain knowledge.
  * `data-catalogs-and-semantic-layers.md`. The "we already have Collibra / a dbt Semantic Layer" objection, and the export-and-cite composition.
  * `knowledge-graphs-and-ontologies.md`. The "why not RDF?" question, why OKF refuses typed edges, and what that costs (no inference, no query language, no edge filtering).
  * `long-context.md`. The "windows keep growing" objection, built on the position effect already cited in `context/`.
  * `retrieval-and-okf-together.md`. Four compose patterns over an existing retrieval stack, plus a four-check diagnostic for whether that stack is actually failing.
  * Cross-links added into `spec/cross-linking.md`, `spec/non-goals.md`, `spec/versioning.md`, `ecosystem/okf-skill.md`, `practice/progressive-disclosure.md`, `context/context-window.md`, `context/scattered-knowledge.md`, `approaches/okf-versus-retrieval.md`, `approaches/retrieval-failure-modes.md` and `overview.md`, so each new concept is reachable from the existing prose rather than only from the index.
  * Sources verified before citing: `agentskills.io`, the dbt Semantic Layer docs, and the W3C RDF 1.1 Primer (a Working Group Note from 2014, not a Recommendation).
* **Update**: Researched the state of the community and added four snapshot concepts under `ecosystem/`. Now 60 concepts. Measured from the upstream repository and issue tracker on 2026-08-05, not from secondary coverage.
  * `adoption.md`. Hard numbers (8,306 stars, 703 forks, 100 issues from 73 distinct authors, 20 open PRs) and the distinction the word "adoption" hides: building on OKF, positioning as OKF-compatible, and running it in production are three different claims. GitBook is the worked example of the second.
  * `community-tools.md`. Ten independent tools, each verified against its repository for stars, license and last push. Largest is `okf-gem` at 118 stars. Notes that AKB reports arriving at OKF's core model independently before the spec existed.
  * `open-questions.md`. The seven live debates: typed relationships (converging on two edges with query-time semantics, not an ontology), trust splitting into four axes, invisible deletion, brittle path-identity, `okf_profile`, v0.2 errata, and the spec-versus-visualizer gap. Plus what Google is building, read from merged commits: a Semantic Model IR in `mdcode` that emits BigQuery property-graph DDL, and Confluence/SharePoint ingestion in the enrichment agent.
  * `governance.md`. The format lives in one directory of one vendor's repo. Four requested gaps (its own repository, an authoritative site, a discussion venue, a community index) plus a conformance corpus. What is working, and what to build on versus what to keep a margin on.
  * All four carry `status: draft` and `stale_after: 2026-11-05`, because they are dated readings rather than facts. This is the first use of the lifecycle fields in this bundle for their actual purpose.
* **Update**: Structure audit, and one self-inconsistency fixed. Twelve concepts carried the generic `type: Concept`, which `spec/core-frontmatter.md` explicitly names as a poor value alongside `Document` and `Page`. A bundle that teaches type discipline should not be the counter-example. Retyped to `Primer` (the four `context/` orientation concepts), `Rationale` (design principles, non-goals, why trust became a field), `Comparison` (format versus protocol and the llms.txt stack, aligning them with the two existing X-versus-Y concepts), `Practice` (progressive disclosure, distribution) and `Analysis` (the retrieval failure modes). `Concept` no longer appears: 62 concepts across 13 descriptive types.
  * `overview.md` gains a type legend, since `type` is what a consumer routes and filters on and this bundle had never published its own vocabulary. It also flags that every `Field Report` carries `status: draft` and `stale_after`, so a consumer can exclude the dated snapshots in one predicate.
  * Audit results recorded for the next pass: index coverage is complete, the graph has no orphan or weak node (minimum degree 7), 442 links are woven into prose against 133 in `# Related` sections with no concept relying on the list alone, heading discipline is uniform, and the no-slop mean is 0.94 violations per 100 words across 62 files with a worst case of 2.90.
* **Update**: Added `practice/first-bundle.md` and a real example bundle at `bundles/hello-okf/`. The bundle had a single-concept example and a procedure, but nothing a newcomer could copy: `practice/adoption-path.md` said "write the five files" and never showed them. Now 62 concepts.
  * `bundles/hello-okf/` is a separate five-concept bundle answering "how many active customers do we have?": the metric, the policy behind its 90-day window, the table it reads, the sanctioned query as an `Attested Computation`, and the known issue that makes naive counts wrong by ~8%. Flat, no subdirectories, no `verified`. It is validated by the repo gate like any other bundle, so the example proves its own conformance instead of asserting it.
  * `practice/first-bundle.md` walks it: the one-file minimum that already conforms, why those five kinds of file generalize, what each demonstrates, and what the example deliberately omits (no `verified`, no subdirectories, no `README.md`).
  * `practice/index.md` gains a "Start here" section, and `overview.md` a reading-order row for writing a bundle in the next hour rather than this week.
* **Update**: Surveyed all 145 upstream pull requests, which sharpened the governance picture considerably and turned up material the issue tracker alone had not shown.
  * `ecosystem/governance.md` gains a measured throughput section: 72 open PRs, 41 merged, 59 distinct PR authors, 61 open non-dependabot PRs at a median age of 39 days and an oldest of 71. All 41 merged PRs come from the same 13 recurring committers, and no community contribution found in this survey has landed. Three worked examples of the cost: PR #50 proposed `sources` and v0.2 shipped it separately while the PR stayed open; PR #58 identified the §6/§11 index-frontmatter contradiction that v0.2 then resolved, and also holds the trust-and-safety section later threads cite as though it were part of the spec; PR #66 fixed the reference-viewer link bug and two contributors have since re-fixed the same defect independently.

  * `ecosystem/community-tools.md` gains the projects PR #167 surfaced (okf-lint, okf-conformance, okf-frontmatter, okf-knowledge, a second Go CLI), notes that Kiso emits `llms.txt` and a sitemap alongside published bundles, and records that the best curated tool index is itself a pending pull request.
  * `spec/conformance.md` gains the `README.md` trap: a plain README inside a bundle is a non-reserved `.md` file, so it is treated as a concept and fails the one rule. Proposed for exemption upstream since June, unmerged.
* **Update**: Added `approaches/llm-wikis.md`, tracing OKF's descent from the LLM wiki pattern (Karpathy's gist, 4 April 2026) published ten weeks before OKF v0.1. The gist proposes `index.md` and `log.md` with the meanings OKF later reserved. Answers whether the pattern and second-brain knowledge bases are dead: the pattern was standardized rather than replaced, an Obsidian vault is already most of a bundle, and the remaining seam is wikilink syntax. Cross-linked from `spec/bundle.md` (the reserved names are inherited), `spec/non-goals.md` and `approaches/index.md`. Now 61 concepts.

Re-measured on 2026-08-05 from the `open-knowledge-format` GitHub topic (108 repositories) and the BundleDex directory (479 bundles, 395 authors, 198 conformant).
